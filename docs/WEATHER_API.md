## 接下来逐步做（从你当前进度继续）

### 步骤 A：用开发者工具打开云开发（部署函数）

1. 打开 **微信开发者工具**，导入本项目（AppID 用小程序真实 AppID）
2. 点顶部 **云开发**（云朵图标）
3. 确认进入的是环境：`cloudbase-d5gkkts0se795c6b3`
4. 左侧找到 **云函数**
5. 在项目文件树找到 `cloudfunctions/getWeather`
6. **右键** `getWeather` → **上传并部署：云端安装依赖**
7. 等到提示部署成功（首次可能要一两分钟）

若列表里还没有 `getWeather`：先确认 `project.config.json` 里有 `"cloudfunctionRoot": "cloudfunctions/"`，然后对文件夹再右键上传一次。

### 步骤 B：给云函数配置环境变量（放 Key 的地方）

任选一种入口：

**方式 1（推荐，开发者工具内）**

1. 云开发控制台 → **云函数** → 点开 `getWeather`
2. 打开 **配置 / 环境变量**
3. 新增：

| 变量名 | 值 |
|--------|-----|
| `QWEATHER_KEY` | （粘贴和风 API KEY） |
| `DEFAULT_CITY` | `宣城` |

4. 保存  
5. 如提示需重新部署，再右键部署一次 `getWeather`

**方式 2（浏览器）**

1. 公众平台 → 云服务 → 云开发 → **管理环境**
2. 进入后找 **云函数** → `getWeather` → 配置 → 环境变量  
3. 同上填写并保存

### 步骤 C：小程序端设置

1. 模拟器打开小程序 → **我的**
2. **天气城市** → 填 `宣城`（或你家城市）
3. **关闭「演示模式」**（演示开着会故意用假天气）
4. 重新点编译
5. 打开 **陪陪我**，看默认状态天气标签（如 `宣城 · 晴 12°C`）

### 步骤 D：如何确认是真天气

1. 开发者工具 → 云开发 → 云函数 → `getWeather` → **日志**
2. 触发一次首页加载后，日志结果里应有 `"source": "qweather"`
3. 若是 `"source": "fallback"`：Key/网络/生效延迟问题，会自动假数据，不会白屏

## 不要做的事

| 错误做法 | 原因 |
|----------|------|
| 把 Key 写进 `app.js` / 页面 JS | 会泄露，别人能刷爆你的额度 |
| 填到公众平台「API 安全」 | 那是微信自己的密钥，不是和风 |
| 只开云环境却不部署 `getWeather` | 小程序调用会失败并回退假数据 |
| 演示模式开着却期望真天气 | 代码在演示模式下故意走 mock |

---

## 常见问题

| 问题 | 处理 |
|------|------|
| 云开发点不了 | 必须用真实 AppID（你已有「给妈妈的小棉袄」） |
| 关了演示仍是假天气 | 查：函数是否部署、环境变量是否保存、和风是否还在 1～2 小时生效期 |
| 城市不对 | 「我的」改天气城市，或改 `DEFAULT_CITY` |
| 想换天气服务 | 只改云函数 `getWeather`，小程序不用动 |

备案审核中也可以先部署调试；正式全网发布通常需备案完成后再发版。
