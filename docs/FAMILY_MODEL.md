# 家庭数据怎么设计（爸妈 / 多家庭）

## 结论（推荐）

**不要**给爸爸、妈妈各建一套时光轴。  
**要**「一个家庭一份数据 + 按身份改称呼」。

```text
family（家庭）
  ├─ members: 女儿 / 妈妈 / 爸爸 /（以后可加祖辈）
  └─ timeline: 语音、心意、纸条（全家人共享）

首页问候文案 & 录音
  └─ 按「当前打开的人是谁」显示：妈… / 爸…
```

## 为什么不拆两套数据？

| 拆成爸一份妈一份 | 一个家庭共享 |
|------------------|--------------|
| 你发语音要发两次 | 发一次双方都看得到 |
| 心意统计对不上 | 家庭总账清晰 |
| 以后亲戚更难扩展 | 加成员只加角色 |

爸爸打开若仍写「妈」，怪的是**文案**，不是数据。用身份个性化即可。

## 以后别的家庭要用？

已经按 `familyId` 隔离：

1. 你创建家庭 → 得到邀请码  
2. 另一家人各自开家庭 → 另一套 `familyId`  
3. 云数据库规则：只能读自己的 `familyId`

同一套小程序代码，多家庭互不影响。

## 心意卡片怎么标「来自谁」？

可选字段（以后可加）：

```js
direction: 'parent_to_daughter' | 'daughter_to_parent'
fromRole: 'mom' | 'dad' | 'daughter'
```

列表显示：「妈妈的心意」「爸爸的心意」。  
当前 MVP 可用中性「家长的心意」，避免爸爸看到满屏「妈妈」。
